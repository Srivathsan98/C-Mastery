How to use it

  • Create one repo or one folder per roadmap concept.
  • For each concept, maintain: notes.md, questions.md, mistakes.md, mini-project/, and revision-log.md.
  • Every question answered should produce either a written explanation, code sample, or bug reproduction.
  • Mark a concept complete only after you can explain it, code it, debug it, and teach it.

Strength rules

You are not training for comfort. You are training for repeatable competence under pressure.

Proof of mastery checklist

  • Can explain the concept without reading notes.
  • Can write a clean example from scratch.
  • Can find and fix a broken version.
  • Can answer beginner, intermediate, and advanced questions aloud.
  • Can connect the concept to real projects, especially systems or embedded work.
